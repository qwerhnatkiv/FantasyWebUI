> # ⛔ ПРАВИЛО ОТЧЁТА О МЕТРИКАХ. НАРУШЕНИЮ НЕ ПОДЛЕЖИТ
>
> **КАЖДЫЙ шаг. КАЖДАЯ проверенная гипотеза. КАЖДЫЙ ответ, в котором есть хоть одно число о качестве
> модели — это ТАБЛИЦА. Столбцы строго в этом порядке:**
>
> | метрика | ОФО 1 (справка) | ОФО 2 (справка) | планка | BASELINE (*каким шагом получен*) | проверяемый шаг 1 | проверяемый шаг 2 | … |
> | --- | --- | --- | --- | --- | --- | --- | --- |
> | RMSE (< лучше) | | | | | | | |
> | MAE (< лучше) | | | | | | | |
> | R² (> лучше) | | | | | | | |
> | Спирмен (порядок, > лучше) | | | | | | | |
> | Спирмен (топ-20%, > лучше) | | | | | | | |
>
> **Строк ровно пять, и каждая с указанием направления.** Значения — АБСОЛЮТНЫЕ. Столбец BASELINE
> обязан нести пояснение, каким именно шагом он получен. ОФО 1 и ОФО 2 — замороженные константы, их
> копируют, а не считают.
>
> **ЗАПРЕЩЕНО:** сообщать результат дельтой в тексте вместо таблицы (`MAE −0.0198`, `взято 56%
> потолка`, `+0.0066, из которых +0.0051 контроль` — так писать НЕЛЬЗЯ, это нечитаемо: не видно, от
> чего дельта, и проверить её невозможно). Дельта и счёт по зёрнам допустимы ОДНОЙ строкой ПОСЛЕ
> таблицы, но никогда вместо неё.
>
> **BASELINE ВСЕГДА РОВНО ОДИН — В ЛЮБОЙ МОМЕНТ ВРЕМЕНИ.** Не бывает «baseline утром» и «baseline
> вечером», «baseline до обеда» и «baseline после дождичка в четверг». Есть BASELINE, и есть всё
> остальное — а всё остальное словом «baseline» НЕ НАЗЫВАЕТСЯ ВООБЩЕ, ни с какими уточнениями.
> Снятый с baseline шаг в таблице подписывается тем, чем он является («аффинная прямая», «вероятность
> из ЭЛО»), и пометкой, что он снят. Столбец BASELINE один, и он несёт пояснение, каким шагом получен.
>
> **СТОЛБЕЦ НАЗЫВАЕТСЯ ИМЕНЕМ ШАГА.** Тем самым, которым шаг называют в разговоре — «бонус за 10
> мин», «изотоника», «кэф вместо ЭЛО». НЕ описанием метода («поправка по вероятности»), не внутренним
> именем из кода, не сокращением. Читатель обязан найти нужный столбец глазами за секунду, не
> расшифровывая. Если у шага ещё нет имени — сначала дать имя, потом строить таблицу.
>
> **ВСЁ СЧИТАЕТСЯ НА ПЯТИ ЗЁРНАХ (`42`-`46`). ВСЕГДА.** Это касается не только BASELINE: любой
> проверяемый шаг считается на всех пяти, и в таблицу идёт ансамбль. Одно число, снятое на одном
> зерне, — не результат.
>
> **РЕШАЮТ МЕТРИКИ. Пять чисел в таблице — и есть ответ.** Все пять смотрят в одну сторону — решение
> принято, считать больше нечего. Никаких дополнительных прогонов в этом случае НЕ ДЕЛАТЬ: они стоят
> удвоения времени и ничего не добавляют. Заказчик читает таблицу и решает по ней, и это правильно.
>
> Два инструмента ниже — НЕ обязательный ритуал. У каждого ровно один случай применения:
>
> - **СЧЁТ ПО ЗЁРНАМ** («лучше на N из 5» по каждой метрике) — только когда метрики РАСХОДЯТСЯ, часть
>   вверх, часть вниз, и по таблице ответа нет. Разброс топ-20% от одного лишь зерна обучения на этих
>   данных `0.0056`…`0.0090`, то есть больше почти любого измеряемого эффекта; когда таблица
>   противоречива, счёт разрубает, а когда согласна — молчит о том же самом.
> - **КОНТРОЛЬНАЯ РУКА** (та же конструкция с обессмысленной осью: перемешанные значения, ось
>   заменена константой) — только когда результат меняет ПЛАН РАБОТ, то есть когда собираешься звать
>   заказчика вкладываться в направление. Она отвечает не «принять или отклонить», а «стоит ли копать
>   здесь дальше». Пример, ради которого правило и существует: подмена ЭЛО на кэфы дала топ-20%
>   `+0.0066` и была принята по метрикам совершенно верно, но контроль показал, что рынку принадлежит
>   `+0.0015`, а остальное — цена появления новых колонок. Решение не изменилось; изменилось то, что
>   не надо тратить дни на добивание покрытия ценами.
>
> **Историю правила держать честно.** `2026-09-06` здесь было написано «контроль обязателен всегда» —
> это перегиб, сделанный после того, как интерпретацию едва не выдали за результат. `2026-09-07`
> заказчик его снял: правильная реакция была не «контроль всегда», а «не выдавать интерпретацию за
> результат».
>
> **ТАБЛИЦА ИДЁТ И В ЧАТ, И В ФАЙЛ. Не одно из двух — оба.**
>
> **ЗАКАЗЧИК ТРЕБОВАЛ ЭТОГО БОЛЕЕ ПЯТИДЕСЯТИ РАЗ.** Каждое нарушение он ловил сам и объяснял заново.

Angular 17.3 frontend for the fantasy hockey project: calendar of games, player stats table, squad
builder, and date-range driven expected-fantasy-points ("EFP") projections.

## Running locally

```powershell
npm install
npm start
```

`npm start` runs `ng serve --ssl` with an ASP.NET dev cert and serves on **:4200**. If the cert step
fails, trust it once with `dotnet dev-certs https --trust`.

**Local dev talks to the production backend by default** — the API base URL is hardcoded in
`src/services/api/api.service.ts` rather than read from an environment file. Pointing the app at a
locally running `FantasyWeb` means editing those URLs or wiring up `src/proxy.conf.js`, which is
currently unused.
